# Security hardening and rollout

This release closes the identified source-level privacy and trust gaps. It is not a claim that the product is unhackable, a penetration-test certificate, or proof of live Firebase/IAM configuration. Treat phones and their location/selfie assertions as untrusted, even when attested.

## Changes

- Passenger maps use authenticated, rate-limited server endpoints. Nearby previews are bounded to 12 km, 40 anonymous markers, roughly 100-metre coordinate precision and fresh presence. They exclude busy/unapproved/unfunded drivers. Exact tracking verifies the caller's authoritative active passenger ride and assigned driver. No fallback reads the private fleet feed.
- Realtime Database denies fleet-wide client reads. Drivers can read/write only their own presence, after `prepareDriverAvailability` grants server-owned access. Clients cannot change an existing ride pointer or submit far-future heartbeat timestamps. Dispatch still reads privately through the Admin SDK.
- Legacy passenger photos are owner/admin only. Existing approved licence images cannot be overwritten without returning the driver to review; selfie objects cannot be overwritten. Uploads remain size/type restricted. Manual admin review remains necessary: device-reported face checks are not identity proof.
- Unverified preflight requests return a generic response without revealing whether a phone is registered or which role it has. Phone ownership and role conflicts are checked after OTP.
- All callable functions use one wrapper: Firebase verifies the token, then the wrapper rejects missing Auth users, disabled/revoked sessions and deleted accounts. It bounds request size and applies a persistent per-user budget (240/minute), plus a hashed network budget for unauthenticated preflight. Paid passenger ride creation checks role and has an additional 8/minute budget. Nearby/assigned location budgets are 30/60 per minute.
- Both apps initialize Firebase App Check using Play Integrity / App Attest with Device Check fallback. A registered debug provider is available only in debug builds with `--dart-define=ALPHA_APP_CHECK_DEBUG=true`. No debug token is committed or accepted specially by the server. Attestation is additive; it does not replace ownership, role, fare or wallet validation.
- Passenger production builds no longer use debug signing. Both production builds require a configured private keystore; GitHub CI may create unsigned release bundles for build verification only. Native apps disable cleartext traffic and OS backup.
- Driver profile writes cannot set arbitrary administrator/provenance fields or delete/recreate the profile directly. Fare tracking no longer grants a per-request movement floor and rejected teleports retain the previous trusted location.
- Admin/dispatcher hosting adds CSP/HSTS and browser permissions restrictions. Leaflet's fixed external assets have integrity hashes. Web App Check initialization is ready for the public Enterprise site key in `admin/security-config.js`.
- Backend dependency lockfile receives compatible security updates; repeat `npm --prefix functions audit` when releasing because advisory status changes.

## Rollout order — do not close the location feed before updating clients

1. Pull both repositories. From `C:\Projects\Alpha`, run `npm --prefix functions ci`, then deploy `firebase deploy --project alpha-ride-29708 --only "functions,hosting"` with `FUNCTIONS_DISCOVERY_TIMEOUT=60`. Leave **ALPHA_ENFORCE_APP_CHECK=false** during rollout. Preserve any old regional functions when Firebase asks about deletion until their queue migration is separately verified.
2. Build and install updated APKs for both apps. Debug/profile testing remains supported; release requires `android/key.properties` pointing at the correct existing keystore. Never generate a replacement key for an already published app. Register each signing certificate's SHA-1/SHA-256 in Firebase and the appropriate restricted Maps key. CI's unsigned bundle is not a distributable release.
3. Verify nearby markers, active assigned-driver tracking, driver online/offline/reconnect, OTP, places, profile photos, ride completion, and immediate rebooking on two real devices. Include an older supported phone and each vehicle class. Distribute the updated passenger app to all testers: old APKs that read the entire location feed will intentionally stop showing drivers after step 4.
4. Deploy the access rules from **C:\Projects\Alpha**: `firebase deploy --project alpha-ride-29708 --only "database,firestore:rules,storage"`. Do not deploy rules from an old checkout. Already-online drivers may need one availability refresh to obtain the new presence grant. Driver approval and dispatch remain server checked.
5. Register both Android apps in Firebase App Check with their production SHA-256 certificates and Play Integrity; configure Apple attestation for iOS distribution. Register the admin/dispatcher web app and its actual domains, and put its **public** reCAPTCHA Enterprise site key into `admin/security-config.js`, then deploy hosting. Verify valid tokens in App Check metrics on real distribution builds; configure legitimate sideload/test-device support explicitly rather than bypassing server checks.
6. After all intended clients and admin/dispatcher have valid tokens, set `ALPHA_ENFORCE_APP_CHECK=true` in the ignored `functions/.env.alpha-ride-29708` file and redeploy functions. Enable App Check enforcement for Firestore, Realtime Database and Storage in Firebase Console. These live-console actions have not been performed by this source change. Old/unregistered clients will be rejected once enforced. Test this before a public release; do not disable enforcement as a general error workaround.
7. Revoke previously issued public image download tokens. Tightening Storage rules does **not** revoke old bearer download links. With authorized Application Default Credentials and `GOOGLE_CLOUD_PROJECT=alpha-ride-29708`, run `node functions/tool/revoke_private_download_tokens.js` for a count-only dry run, then add `--apply` after updated apps display authenticated images correctly. It preserves files and uses metadata preconditions. Never send credentials, token values, or download URLs in chat. Expiring signed URLs may remain usable until their expiry.
8. Configure TTL for `security_request_limits.expiresAt`, budget/usage alerts, restricted API keys, least-privilege service accounts and multi-factor authentication for administrator/Google Cloud/GitHub accounts. Verify backup recovery and restrict who can deploy or change admin claims. The repository cannot prove or configure these external account controls without authenticated access.

## Verification

`npm --prefix functions test` covers revoked/deleted identities, budget reset, oversized payloads, private location projection, wrong-role/other-driver/terminal-ride tracking denial, image ownership and GPS jump handling. `firebase.security-tests.json` uses only the synthetic `demo-alpha-security` emulator project. CI runs `security-tests/rules.test.mjs` against real Firestore/Realtime Database/Storage emulators, including direct modified-client attempts to edit wallets, roles, assignments, approvals, presence and private images. Flutter CI analyzes/tests/builds both apps, including the passenger stream switching tests.

Remaining limits: attestation does not prove actual GPS location or the identity in an uploaded photo; plausible fake movement and multi-account abuse need operational fraud detection and independent testing. Per-account/network request limits do not eliminate distributed denial of service or guarantee a fixed cloud bill. No production accounts, balances or photos are deleted by deploying this release.
